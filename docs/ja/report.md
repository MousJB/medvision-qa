# HTML レポート: Version Verification Record（バージョン検証記録）— v0.1

[English](../report.md)

実装: `src/medvision_qa/report.py`、テンプレート `src/medvision_qa/templates/report.html.j2`、
メッセージは `src/medvision_qa/i18n.py`。テスト: `tests/test_report.py`、`tests/test_i18n.py`。

```bash
python -m medvision_qa config.toml -o report.html               # 英語
python -m medvision_qa config.toml -o report.ja.html --lang ja  # 日本語
```

終了コード: レポートを生成した場合は判定結果にかかわらず `0`、設定ファイルまたはデータが
不正な場合は `2`。後者の場合、レポートは作成されず、エラーが表示されます。

## 1. 保証している性質（テスト済み）

| 性質 | 方法 |
|---|---|
| 仕様書（第 10 節）の 21 節を順番どおりに含む | `<h2 id="s1">` から `<h2 id="s21">` |
| 「What This Report Cannot Establish」の最低限の文言 | 定数 `CANNOT_ESTABLISH` を全文表示 |
| データを捏造しない | すべて `EvaluationResult` から取得。空のフィールドはその場で「未提供」と表示し、**さらに**第 19 節にまとめる |
| 数値が計算結果と一致 | 信頼区間、根拠、混同行列、ハッシュを計算済みオブジェクトと照合 |
| 自己完結 | CSS はインライン、スクリプト・外部 URL・リモートフォントなし |
| 利用者のテキストをエスケープ | タイトル、説明、根拠は Jinja2 の HTML エスケープを通す |
| 絶対パスを含まない | ファイルは設定ファイルからの相対パスで表示（ユーザー名やローカルのフォルダー構成を出さない） |
| 再現可能 | 同じ設定 → 実行 ID と時刻を除いて同一のレポート。どの OS でも改行は LF |
| サンプルサイズの 4 状態 | `Provided`、`Not provided`、`Not applicable`、`Based on data availability`（＋警告）。実際のサイズは常に別に表示 |
| 2 言語 | 英語（既定）と日本語で同じ内容を表示（同じ節、同じ数値、同じ表のセル。テスト済み） |

## 2. 各節の内容

| 節 | 内容 | 出所 |
|---|---|---|
| 1 | 識別子 | 実行の UUID（レポートの識別子を兼ねる）、設定ファイルの SHA-256 |
| 2 | 日時 | 実行開始時刻（UTC） |
| 3 | 目的 | `evaluation.title`、`evaluation.objective`、比較の種類、症例数 |
| 4 | バージョン | `versions.*.id`、説明、スコアの有無 |
| 5 | コードと重み | **申告された** `code_commit`、`weights_sha256`（重みファイルは読み込まない） |
| 6 | データセット | `data.description`、`data.nature`、`data.manifest_sha256` |
| 7 | 来歴 | 各 CSV の相対パス、**計算した** SHA-256、行数 |
| 8 | 前処理、依存パッケージ | `versions.*.preprocessing`、乱数シード、許容誤差、Python、パッケージのバージョン |
| 9 | クラス | インデックス付きの順序、派生二値タスク |
| 10 | 検証 | 正解データのモード、照合、ファイルごとに実施したチェック |
| 11 | 指標 | バージョンごとの推定値と信頼区間、未定義の理由、警告、定義 |
| 12 | 混同行列 | バージョンごとに 1 つ |
| 13 | 信頼区間のパラメーター | 手法、水準、抽出回数、乱数シード、単位と単位数 |
| 14 | 統計的検定 | 対応のある Δ = B − A、マクネマー検定（または適用できない理由）、DeLong 法の状態 |
| 15 | 基準 | 各基準の定義、設定ファイルのハッシュ |
| 16 | 判定 | 基準ごとの状態と根拠、総合判定、集約規則 |
| 17 | サンプルサイズ | 実際のサイズ、状態、記載内容、該当する場合は警告 |
| 18 | 頑健性 | 「未実施」（v0.1 では未対応） |
| 19 | 利用できない項目 | 自動生成の一覧: 欠けているメタデータ、未定義の指標、適用できない検定 |
| 20 | 限界 | データに応じて自動生成した一覧（データの種類、`patient_id`、多重性など）と一般的な限界 |
| 21 | What This Report Cannot Establish | 仕様書で定めた固定の文言 |

## 3. 言語

すべての見出しと、自動生成される文（根拠、未定義の理由、限界など）は、メッセージカタログ
`src/medvision_qa/i18n.py` から取得します。各項目に英語と日本語の文が対になって入っています。
判定エンジンはメッセージを「キー＋パラメーター」の形で保持するため、1 回の評価結果を
どちらの言語でも表示できます。`tests/test_i18n.py` では、両言語で同じプレースホルダーを
使っていること、コード内で使うキーがすべて存在することを確認しています。

設定ファイルの自由記述（タイトル、目的、説明）は記載どおりに表示されます。レポートを
すべて日本語にする場合は、これらを日本語で書いてください（`examples/synthetic_demo/config.ja.toml`
を参照）。

## 4. 既知の制約

- グラフ（ROC 曲線など）はなく、表のみです。
- 申告されたメタデータ（コミット、重みのハッシュ、前処理）はそのまま表示します。実際に
  使ったモデルと一致しているかどうかは、本ツールでは確認できません。
