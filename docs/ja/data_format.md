# 入力ファイルの形式 — v0.1

[English](../data_format.md)

状態: フェーズ 0 で定義し、**フェーズ 1 で実装**（`src/medvision_qa/validation.py`、
`src/medvision_qa/alignment.py`）。テストは `tests/test_validation.py` と
`tests/test_alignment.py`。暗黙の型変換を避けるため、pandas ではなく標準の `csv`
モジュールで読み込みます。

「行」はファイル上の物理的な行を指します（1 = ヘッダー行）。引用符で囲まれたフィールドに
改行が含まれる場合、レコード番号とは一致しないことがあります。

基本方針: **違反はすべて、処理を止めるエラーとして扱います。** 行を削除したり、値を
黙って修正・正規化・置換したりすることは一切ありません。

---

## 1. すべての CSV に共通する規則

| 規則 | 動作 |
|---|---|
| 文字コード | UTF-8（BOM の有無は問わない。Excel は BOM を付ける）。それ以外 → エラー |
| 区切り文字 | カンマ `,`。引用符の扱いは RFC 4180 に従う |
| ヘッダー行 | 必須。1 行目に置く |
| 列名の重複 | エラー |
| 不明な列 | エラー。ただし `meta_` で始まる列は保持する（計算には一切使用しない） |
| 空行、フィールド数の不一致 | 行番号付きのエラー |
| 値の先頭・末尾の空白 | エラー（暗黙の `strip()` は行わない） |
| データ行のないファイル | エラー |

各エラーには、ファイル、行番号（1 = ヘッダー行）、列、問題の値、違反した規則が示されます。

## 2. クラス

クラスはデータから推定せず、評価設定ファイル（[evaluation_config.md](evaluation_config.md)）で
**宣言**します。

- 順序付きのリストで、2 クラス以上、重複なし。
- 名前は `^[A-Za-z0-9_-]+$`。大文字と小文字を区別する（`Glioma` ≠ `glioma`）。
- 宣言した順序が、混同行列の行・列の順序と、スコア列の想定順序を決める。
- 宣言したクラスがデータに存在しなくても形式エラーにはならない。ただし、そのクラスに
  依存する指標は**未定義**として扱う（フェーズ 1）。

MRI データセットの例: `["glioma", "meningioma", "notumor", "pituitary"]`

### 陽性クラス（派生二値タスク）

`positive` は宣言済みクラスの空でないリストで、全クラスと同一であってはなりません。
「陽性クラス 対 その他」の二値タスクを定義します。

- 二値の正解: `true_label ∈ positive`
- 二値の予測: `predicted_label ∈ positive`（既存の多クラス判定をそのまま使い、新たな閾値は設けない）
- 二値のスコア: 陽性クラスの `score_<クラス>` の合計（AUROC の計算にのみ使用）

MRI の例（腫瘍 対 腫瘍なし）: `positive = ["glioma", "meningioma", "pituitary"]`
一対他: `positive = ["glioma"]`

## 3. 正解データファイル（`ground_truth.csv`）

基準ラベルの唯一の出所であり、バージョン A と B で共有します。

| 列 | 必須 | 型 | 規則 |
|---|---|---|---|
| `case_id` | はい | テキスト | 空でなく、ファイル内で一意 |
| `true_label` | はい | テキスト | 宣言済みクラスのいずれか |
| `patient_id` | いいえ | テキスト | 列がある場合は空不可。複数の症例が同じ患者を共有してよい |
| `meta_*` | いいえ | テキスト | 計算では無視する |

`patient_id` がない場合、推論はすべて**画像（症例）単位**となり、レポートにもその旨が
記載されます。`patient_id` がある場合は、患者単位でリサンプリングします（クラスター・
ブートストラップ）。

```csv
case_id,true_label,patient_id
img_0001,glioma,P001
img_0002,notumor,P002
```

---

## 4. 予測ファイル（バージョンごとに 1 つ）

| 列 | 必須 | 型 | 規則 |
|---|---|---|---|
| `case_id` | はい | テキスト | 空でなく、ファイル内で一意 |
| `predicted_label` | はい | テキスト | 宣言済みクラスのいずれか |
| `score_<クラス>` | いいえ（ただし**全部か無しか**） | 実数 | 宣言済みクラスごとに 1 列。余分な列は不可 |
| `true_label` | いいえ | テキスト | § 5 を参照 |
| `meta_*` | いいえ | テキスト | 計算では無視する |

### スコアの規則

`score_*` 列が 1 つでもある場合:

1. 宣言済みクラスごとに過不足なく 1 列ずつ必要。
2. 各値は `[0, 1]` の有限の実数（`nan`、`inf`、空欄 → エラー）。
3. 各行の合計は許容誤差の範囲で 1（既定値 `1e-3`。設定可能で、レポートにも記載）。
   つまりスコアは softmax のような出力である必要がある。
4. `predicted_label` は最大スコアのクラスのいずれか（argmax。同点の場合はどのクラスでも可）。
   一致しなければエラー。v0.1 は閾値による判定規則には対応していない。

スコアがない場合、スコアに基づく指標（AUROC）は推定せず、**利用不可**とします。

```csv
case_id,predicted_label,score_glioma,score_meningioma,score_notumor,score_pituitary
img_0001,glioma,0.91,0.05,0.02,0.02
img_0002,notumor,0.03,0.10,0.80,0.07
```

## 5. 正解ラベルの置き場所

2 つのモードがあり、どちらか一方を設定ファイルで明示します。

- **`separate_file` モード（推奨）**: `ground_truth.csv` を 1 つ用意する。予測ファイルにも
  `true_label` がある場合、すべての値が正解データファイルと一致していなければエラー。
- **`embedded` モード**: 別ファイルを使わず、各予測ファイルに `true_label` を含める。
  A/B 比較では、各 `case_id` の `true_label` が A と B で一致していなければエラー。
  このモードでは `patient_id` は使えない。

---

## 6. 症例の照合

- 照合は **`case_id` のみ**で、文字列の完全一致により行う。行の順序は関係ない。
- 2 つのファイルを、位置や行数で対応付けることは決してない。
- 正解データ、A、B の `case_id` の集合は**完全に一致**していなければならない。過不足が
  あればエラーとなり、該当する ID の一覧が示される。
- 共通する症例だけを残す「共通部分」モードはない。一部の症例だけを使う場合は、事前に
  選び出し、その手順を記録しておくこと。

---

## 7. v0.1 形式の既知の制約

- 単一ラベルの分類のみ（マルチラベルやセグメンテーションは対象外）。
- 1 列だけの二値スコアには対応しない。二値タスクでも 2 列とも記載すること。
- `case_id` が A と B で本当に同じ画像を指しているかは、この形式では確認できない。
  確認できるのは ID の一貫性のみである。この点の追跡には、データマニフェストのハッシュ
  （`data.manifest_sha256`）を用いる。
