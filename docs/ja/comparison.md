# 2 つのバージョンの比較 — v0.1

[English](../comparison.md)

実装: `src/medvision_qa/comparison.py`、`src/medvision_qa/decision_engine.py`、
`src/medvision_qa/evaluation.py`。テスト: `tests/test_comparison.py`、
`tests/test_decision_engine.py`、`tests/test_evaluation.py`。

前提: 2 つのバージョンは**まったく同じ症例**で評価されていること（照合処理で確認する。
[data_format.md](data_format.md#6-症例の照合) を参照）。

## 1. 対応のあるブートストラップによる差

[metrics.md](metrics.md) の各指標について、Δ = B − A を求めます（正の値 = B のほうが良い）。

- 各抽出で、A と B に**同じ**症例（または患者）のインデックスを使います。これにより対応関係を
  活かせます。A と B の相関によって Δ の不確実性が小さくなるためです。あるテストでは、
  400 症例で accuracy がそれぞれ約 0.75（不確実性は約 ±0.04）であるのに対し、Δ の信頼区間の
  幅は 0.03 未満になっています。
- 手法、乱数シード、単位、未定義の扱いは [metrics.md の第 3 節](metrics.md#3-信頼区間)と
  同じです。A または B のどちらかで指標が未定義なら、Δ も未定義です。
- **AUROC**: AUROC の差もこの方法で推定します。**DeLong 法は実装していません。**
  検証に使える独立した参照実装（R/pROC）がないためです。この状態はすべての結果に記録されます
  （`EvaluationResult.delong_status`）。

## 2. マクネマー検定（参考値）

- 対応のある**正誤**を対象とします。各症例は A と B それぞれについて正解か不正解かのどちらかです。
  b = A のみ正解、c = B のみ正解。
- **正確条件付き**検定: b + c 件中の b について、p = ½ の両側二項検定（`scipy.stats.binomtest`）。
  テスト内で手書きした閉形式 2·P(X ≤ min(b, c)) と照合して確認しています。χ² 近似と異なり、
  不一致ペアが少なくても有効なため、正確検定を採用しました。
- 次の場合は理由を添えて**適用不可**とします。
  - 同じ患者に属する症例が複数ある（ペアが独立ではない）。
  - 不一致ペアがない（b + c = 0）。
- マクネマー検定は**判定には使いません**。判定は信頼区間に基づきます（第 3 節）。
  p 値が大きくても、同等性や性能低下がないことの証明にはなりません。

## 3. 判定エンジン

規則: [evaluation_config.md の第 3 節](evaluation_config.md#3-受入基準)。実装では、慎重を期す
ための規則を 1 つ追加しています。

- **幅ゼロの信頼区間**（すべての抽出で指標が一定。例: accuracy = 1、または A と B が全症例で
  同一）は `INCONCLUSIVE` とし、`SATISFIED` にはしません。この場合、パーセンタイル・
  ブートストラップでは不確実性を測れないためです。

各基準には、信頼区間、比較対象の量（例: `macro_f1 (B − A)`）、読みやすい根拠
（例: `信頼区間 [-0.0412, 0.0187] が −マージン（-0.0300）を含む。非劣性は示されておらず、
否定もされていない`）が保持されます。根拠はメッセージキーとパラメーターの形で保存されるため、
英語でも日本語でも表示できます。

## 4. 実行の追跡可能性

`run_evaluation(config)` は次の情報を記録します: 実行 ID（UUID4）、UTC 時刻、Python の
バージョン、medvision-qa・numpy・scipy・scikit-learn・jinja2 のバージョン、設定ファイルと
各 CSV の SHA-256、ファイルごとに実施したチェック、ブートストラップのパラメーター、混同行列。

同じ設定で 2 回実行すると、信頼区間と判定は同一になります（テスト済み）。変わるのは
実行 ID と時刻だけです。

## 5. 限界

- Δ は指標の絶対差です。オッズ比や相対差は扱いません。
- 対応のあるブートストラップは、パーセンタイル・ブートストラップの限界（小さい標本、
  境界に近い指標）をそのまま引き継ぎます。
- 各基準は独立に評価し、多重性の調整は行いません。集約規則（総合判定が `SATISFIED` に
  なるのは全基準が `SATISFIED` の場合のみ）は保守的ですが、基準が多いほど偶然による
  `NOT_SATISFIED` の確率は高くなります。
- 基準が分析前に定められたことを本ツールは証明できません
  （[evaluation_config.md の第 4 節](evaluation_config.md#4-分析前に定めた基準について本ツールが保証できることできないこと)を参照）。
